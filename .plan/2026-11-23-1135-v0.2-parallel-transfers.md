# Plan: tong v0.2 — parallel transfers, `--stats`, `--bwlimit`, `--remove-source-files`

## Goal

Ship v0.2.0: parallel file transfers (`--parallel N`), parallel S3 multipart uploads (lifting the 5 GB cap), a global `--bwlimit` throttle, rsync-compatible `--remove-source-files`, and `key=value` `--stats` output — no new mandatory dependencies.

## Background

v0.1 shipped local ⇄ S3 with the driver seam (`Endpoint`, optional capabilities), the engine with a sequential execute phase, and a CLI that parses the full option table and rejects `-c -z -P --stats --bwlimit --remove-source-files` with exit 1. Decisions taken: v0.2 = the four roadmap items **plus** multipart upload (`-P`/progress and resumable uploads stay rejected for later); the parallel knob is a tong extension named `--parallel`; `--bwlimit` follows rsync grammar (KiB/s, K/M/G suffix, `0` = unlimited) as one shared budget across workers and parts, both directions; `--stats` is `key=value` lines, explicitly *not* rsync's block (README will note the divergence); `--remove-source-files` follows rsync — non-directories from the sending side that are part of the transfer list and end up in sync, never directories, nothing removed on failure or `--dry-run`, works for any source scheme (S3 → local deletes objects). Tagging `v0.2.0` stays with the owner.

## Approach

1. **`internal/ratelimit`** — hand-rolled token bucket (`Limiter` with injected clock) + `Reader(r io.Reader)` wrapper that blocks on the shared budget. Table-driven tests with a fake clock. No `x/time/rate` dep, matching the v0.1 hand-rolled-filter discipline.
2. **Engine (`internal/syncengine`)** — extend `Options` with `Parallel int` (default 4), `BWLimit int64` (bytes/s, 0 = off), `Stats bool`, `RemoveSourceFiles bool`:
   - Execute phase becomes a bounded worker pool (semaphore + `WaitGroup`, ~30 lines, no `errgroup` dep). Per-file results, exit-code accumulation, and 24-beats-23 precedence unchanged. Verbose lines print at per-file completion (interleaved, like rsync).
   - The source reader from `Open` is wrapped in the shared limiter before `Create` — backpressure throttles both directions and every multipart part, keeping one global budget.
   - `--remove-source-files`: after a file is successfully in sync (transferred **or** already identical), delete it via the source endpoint's `Delete`. Filtered/size-excluded files aren't in the list → untouched; failure → file keeps, counts toward 23.
   - Stats counters behind a mutex; printed to stdout at end of run (also with `--dry-run` and on partial failure).
3. **S3 multipart** — `internal/storage/s3`: `Create` switches to `feature/s3/manager` `Uploader` (`PartSize` 16 MiB default, `Concurrency` wired from `--parallel`, `LeavePartsOnError=false` since resumable is deferred; mtime via `x-amz-meta-mtime` on `CreateMultipartUpload` metadata). Driver `Options` gains test-overridable `PartSize`/`UploadConcurrency`, not exposed on the CLI.
4. **CLI (`internal/cli`)** — add `--parallel N` (default 4, `0` or negative → usage error); drop `--stats`, `--bwlimit`, `--remove-source-files` from `unsupported()` (`-c -z -P` stay rejected); parse `--bwlimit` with the existing `parseSize` (bytes/s); wire new engine options and `s3.Options.UploadConcurrency`.
5. **Stats format** — final key set fixed in implementation with tests, roughly: `files_total`, `files_transferred`, `files_deleted`, `files_skipped`, `bytes_transferred`, `errors`.
6. **README** — tick the v0.2 roadmap box; rewrite the "Planned" features paragraph (multipart no longer pending; `-P`, resumable, `-c`, server-side copy remain); add `--parallel` to the options table; add a note that `--stats` output is `key=value`, not rsync's summary block.
7. **Tests & verification** — engine tests (memory + local drivers): parallel count integrity, remove-source matrix (transferred / identical / failure / dry-run / dirs kept / S3-source), limiter unit tests with fake clock; MinIO/LocalStack integration: multi-part object via small `PartSize` override, mtime round-trip; then `go mod tidy`, `golangci-lint fmt`, `golangci-lint run --fix`, `go build ./...`, `go test -race ./...`.

## Trade-offs

- **SDK `manager.Uploader` vs hand-rolled multipart**: manager is battle-tested (parallel parts, retries, auto small-file `PutObject`); hand-rolling would give finer throttle control per part at the cost of real code. Throttling the shared source reader already bounds the whole upload, so manager wins.
- **Hand-rolled token bucket vs `golang.org/x/time/rate`**: keeps deps at kong + AWS; a ~50-line limiter with an injectable clock is easy to test deterministically.
- **Worker pool vs `errgroup`**: no new dep; pool semantics we need (bounded, collect per-file results) are simple.
- **Throttle on the source reader only**: one wrap point gives global, bidirectional backpressure instead of instrumenting both `Open` and `Create` (and double-counting).
- **Per-file source removal at completion vs after the whole run**: matches rsync, and a Ctrl-C leaves a consistent partial state.
- **`key=value` stats vs rsync's block**: greppable and human-readable; README documents the divergence.

## Open questions
