# Plan: tong v0.1 — local ⇄ S3 sync

## Goal

Ship a working `tong` binary that syncs local dirs ⇄ Amazon S3 (incl. S3-compatible endpoints) with the v0.1 flag set, `--dry-run`, `--delete`, filters, and rsync exit codes — built on a driver-based storage abstraction ready for GCS/Azure later.

## Background

Repo is a fresh scaffold (no `.go` files, kong already in `go.mod`). The README defines the full CLI contract: `tong [OPTION]... SRC... [DEST]`, rsync-style flags/exit codes, roadmap v0.1 = "local ⇄ S3: core flags, `--dry-run`, `--delete`, filters, exit codes". Decisions: full flag grammar in kong with unimplemented flags rejected (exit 1); `--s3-endpoint` in v0.1 (path-style addressing forced when set, for MinIO/R2); `-P` treated as v0.2 alongside `--stats`/`--bwlimit` (parsed, rejected with exit 1); `aws-sdk-go-v2`; layered `cmd/` + `internal/` with sync logic strictly separated from storage drivers; `v0.1.0` tag cut by the owner.

## Approach

1. **Deps**: `go get github.com/aws/aws-sdk-go-v2/config`, `.../s3` (core comes transitively); `go mod download`.
2. **`internal/storage`** — driver seam (the extensibility core):
   - `Endpoint` interface: `List(ctx, prefix, fn func(FileInfo) error)` (streamed/paged, never fully materialized), `Open`, `Create` (accepts mtime metadata), `Delete`; `FileInfo{Key, Size, ModTime, Checksum}`.
   - Optional capability interfaces (server-side `Copier`/`Mover`) declared now, unused until v0.4 — so the engine checks capabilities, not schemes.
   - URL parsing + driver registry: `""`/`file://` → local, `s3://bucket/key` → S3; unknown scheme → exit 3.
3. **`internal/storage/local`** — fs driver: walk-based `List`, mtime set after write, streaming open/create.
4. **`internal/filter`** — rsync-subset matcher: ordered `--include`/`--exclude` rules, first match wins; `*`/`?`/`[...]`, `/` anchoring, `**` crossing separators, trailing-`/` dir-only; `--exclude-from` reads one pattern/line. Hand-rolled (~100 lines, table-driven tests) to avoid a dep.
5. **`internal/syncengine`** — pure logic, no S3/FS imports:
   - Build phase: list src (recursive iff `-r`/`-a`), apply filters + `--max-size`/`--min-size`, compare vs dest (`size+mtime` when `-t`/`-a`, size-only otherwise; `--size-only`, `-u`, `--existing`, `--ignore-existing` override), produce transfer plan + extraneous set for `--delete`.
   - Trailing-slash semantics: `src/` copies contents into dest; `src` copies the dir itself (rsync muscle memory).
   - Execute phase: sequential transfers; `-n` prints plan and exits 0; errors per-file accumulate → exit 23; vanished sources → 24.
   - Tested against local⇄local (`t.TempDir`) plus a small in-memory driver (proves the seam is truly driver-agnostic).
6. **`internal/storage/s3`** — aws-sdk-go-v2 driver: standard credential chain, `--s3-region` → `WithRegion`, `--s3-endpoint` → `WithBaseEndpoint` + forced path-style; paginated `ListObjectsV2`; mtime round-trip via `x-amz-meta-mtime` (epoch seconds; `HeadObject` per key to read it — see trade-offs); `PutObject` w/ SDK default CRC32 checksum verification.
7. **`internal/cli`** — kong grammar for the *full* options table (help shows target CLI); `Srcs []string` positional split in `Run()` (last = dest, ≥2 required — avoids kong multi-positional ambiguity); repeatable `-v` via a tiny custom counter type; combined short flags (`-avn`) work natively. Unimplemented flags (`-c -z -P --stats --bwlimit --remove-source-files`) validated post-parse → usage error, exit 1. Exit-code mapping table (0/1/3/23/24; 2 reserved).
8. **`cmd/tong/main.go`** — thin: parse → wire registry → run → map exit code.
9. **Polish**: tick README checkboxes (Local, S3, S3-compatible); `go mod tidy`, `golangci-lint fmt && golangci-lint run --fix`, `go build ./...`, `go test -race ./...`.
10. **Integration & smoke**: MinIO integration tests for the S3 driver, skipped unless `TONG_TEST_S3_ENDPOINT` is set (no testcontainers dep). Manual smoke: `tong -avn --delete ./dir/ s3://bucket/dir/` then real run, both directions. Tagging `v0.1.0` is yours.

## Trade-offs

- **HEAD-per-object for mtime** vs skipping mtime compare: correctness wins; cost is 1 HEAD/key on the dest walk. Later: parallel HEADs or provider extensions.
- **Single `PutObject`** vs multipart now: v0.1 caps at 5 GB/object; parallel/multipart is explicitly v0.2.
- **Hand-rolled filter matcher** vs `doublestar` dep: rsync subset is enough for v0.1, keeps deps to kong + AWS.
- **Memory driver for engine tests** vs local-only: small extra code, but validates the driver abstraction and keeps engine tests fast.
- **Args split in `Run()`** vs two kong positionals: explicit, avoids greedy-slice ambiguity.
